# Pathwise AI — V4 Architecture & Real-World Robustness Specification

## 1. Core Mission & Architectural Foundations

> **"LLMs generate language and reasoning. Pathwise generates truth."**

Pathwise AI is built to give real, non-technical creators and technical founders the **shortest, most reliable AI tool pipeline** with concrete, copy-paste prompts tailored specifically for their exact project.

---

## 2. Multi-Candidate Scored Classification (`ClassificationConfidence`)

Instead of flat sequential regex branches, Pathwise V4 uses a multi-candidate scoring matrix across 18 canonical project types.

```typescript
export interface ClassificationConfidence {
  projectType: ProjectType;
  confidence: number; // 0.0 to 1.0
  evidence: string[];
  competingTypes: Array<{
    type: ProjectType;
    score: number;
    reason?: string;
  }>;
}
```

### Classification Features:
- **WhatsApp-First & Regional Sellers:** Queries mentioning Instagram, WhatsApp inquiries, or local services (e.g. Nigerian small businesses) map directly to `business_website` with zero-code requirements and WhatsApp CTA integration.
- **Explicit vs Inferred Requirements:** Unknown requirements (like databases, auth, payments) are strictly excluded from architecture unless explicitly requested by the user.
- **Negative Guardrails:** Scope protection exclusions prevent developer bloat on simple showcase projects.

## 3. Normalized 100-Point Suitability Scoring

Every candidate tool is evaluated along an itemized 100-point scoring formula:

```typescript
export interface ItemizedScoreBreakdown {
  taskSuitability: number;     // 0-35 (Certified direct task support)
  requirementCoverage: number; // 0-20 (Capability match)
  constraintFit: number;       // 0-15 (Budget/skill/platform compatibility)
  skillFit: number;            // 0-10 (Matches user skill)
  budgetFit: number;           // 0-15 (Free tier / freemium budget fit)
  platformFit: number;         // 0-10 (Web / desktop support)
  continuity: number;          // 0-10 (Capped tool continuity bonus)
  quality: number;             // 0-5  (Canonical output rating)
  easeOfUse: number;           // 0-5  (Canonical ease of use)
}
```

### Hard Constraints (Pre-Scoring Execution):
- **HC-1 (Budget):** Free-only budget strictly rejects non-free tools.
- **HC-2 (No-Code):** Coding=no strictly rejects developer IDEs (`cursor`, `antigravity`, `windsurf`, `v0-dev`, `replit`).
- **HC-3 (Video):** Video production tasks require `video_generation` capability.
- **HC-4 (Audio):** Music/audio tasks require `music_generation` or `audio_generation`.
- **HC-5 (Voiceover):** Narration tasks require `voice_generation`.
- **HC-6 (Existing Codebase):** Coding tasks on existing repos reject visual no-code website builders.
- **HC-7 (E-Commerce):** Payment/checkout tasks reject portfolio-only visual builders.

## 4. Minimum Viable Toolchain Principle

Pathwise minimizes unnecessary toolchain bloat:
- **Good:** Claude 3.5 Sonnet (Copywriting) ➡️ Framer AI (Design & Build) ➡️ Framer (Domain & WhatsApp Setup) [2 Tools Total].
- **Rejected Bloat:** Claude ➡️ v0 ➡️ Lovable ➡️ Cursor ➡️ Replit [5 Tools for a simple page].

---

## 5. 9-Part Structured Prompt Architecture

All prompts generated by the Prompt Registry follow an actionable 9-part structure:
1. `ROLE`
2. `CONTEXT`
3. `OBJECTIVE`
4. `INPUTS`
5. `REQUIREMENTS`
6. `CONSTRAINTS (NEGATIVE)`
7. `DELIVERABLES`
8. `QUALITY CRITERIA`
9. `OUTPUT FORMAT`

---

## 6. Alternative Tools with Explicit Tradeoffs

Alternatives answer: *"If I don't want the primary tool, what else should I use and what do I trade off?"*
```typescript
export interface AlternativeToolOption {
  tool: Tool;
  score: number;
  reason: string;
  tradeoff: string;
}
```
- Example: **Primary:** Framer AI ➡️ **Alternative:** Webflow (Reason: "Better control over advanced CMS", Tradeoff: "Steeper learning curve").
